# 1. 不实现强制弹出 / No force eject

- 状态：**已接受**（accepted）——当前实现即如此
- 日期：2026-11-07（自初始提交起就在 README 的已知限制中记录）
- 影响面：`src/core/Ejector.*`、README 已知限制

## 背景 / Context

Windows 拒绝弹出时会给出 veto 原因：某个程序还开着文件、某个服务或驱动占着设备。用户希望有一个「强制弹出」按钮，绕过这些检查直接把设备停掉。

## 决策 / Decision

**不实现强制弹出。** 程序只走 `CM_Request_Device_Eject` 的完整 PnP 停止流程，被拒绝时把系统给的原因讲清楚，让用户自己关闭占用者后重试。

## 考虑过的替代方案 / Alternatives considered

- **实现一个带明显警告的强制选项**，先尝试 `FSCTL_DISMOUNT_VOLUME` 再停止设备。没有采纳：它会绕过硬件的安全停止流程，文件系统缓存未落盘时直接拔设备有数据损坏风险，而这个工具的核心价值恰恰是「安全」弹出。
- **静默忽略 veto**。没有采纳：同上，且用户看不到自己正在承担数据损失风险。

## 后果 / Consequences

- 正面：不存在会让用户数据损坏的代码路径；工具的承诺与行为一致。
- 负面：设备被占用时用户必须自己找出并关闭占用者（程序提供「查看打开的文件」作为线索，但不代为关闭）。
- 若将来要做，应作为独立的、默认关闭、有明确警告的选项，并先尝试卸载卷。
