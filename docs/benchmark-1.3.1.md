# USB-Switch 1.3.1 对标与验收记录

2026-11-07。本轮从原仓库的 Windows 安全弹出工具出发，解决多盘识别、弹出受阻、退出读卡器中的一张卡，以及误弹出后的恢复问题。下表记录的是本机观察到的行为，不是所有 USB 设备的兼容性保证。

| 使用场景 | USB-Switch 的交付与验证 | 仍有的边界 |
|---|---|---|
| 找出谁在占用 U 盘 | 最终便携包在 ESD-USB 上遭遇 Windows 拒绝时，JSON 返回了实际持有测试文件的进程 PID；拒绝后文件仍可写。 | 依赖本次 Windows 移除事件。不能保证列出每个文件、每个持有者，也不会关闭进程。 |
| 用键盘找到常用盘 | 在最终便携包上按 Ctrl+Alt+U 打开菜单，输入设备别名，核对配置按实例 ID 保存，重新打开菜单时同时显示别名和原设备名。 | 快捷键用于打开菜单；没有为每个设备分配直接弹出的快捷键。 |
| 双槽读卡器只退一张卡 | 1.3.0 便携包退出 D: 后，原卷不可读，E: 原卷可读。将原卡插回同槽，原 D: 卷可读，USB 读卡器到达时间不变。1.3.1 回归还模拟了第二个分区无法锁定时释放句柄且不发送退卡请求。 | 实机为一台 05E3:0764 双槽读卡器及两张 exFAT 卡；没有实测所有分区布局或型号。 |
| 误弹出后恢复原盘 | ASolid ESD-USB 在旧流程返回 3010。修复后，从托盘弹出、授权、重新连接，原磁盘实例和卷 GUID 在 F: 恢复，目录可读。修复纳入 1.3.1。 | 此入口只保留本次托盘运行最近一次成功移除的目标，依赖设备仍连接及 Windows 保留相应节点。 |
| 脚本、安装与分发 | x64 便携包、安装包、对应 GPL-3.0-only 源码及 SHA-256 均已生成。构建中的 72 项运行时检查通过，另有 CLI、Unicode、托盘、配置迁移与安装器测试。已核对最终文件哈希。 | 未签名、未发布；本机安装器回归不能代替干净 Windows 10/11 环境的验收。 |

## 与现有工具相比

[USB Disk Ejector](https://quickandeasysoftware.net/software/usb-disk-ejector) 的重点是便携、退卡、快捷键及灵活的命令行目标选择，也支持退出程序自身所在的盘。USB-Switch 更适合需要读 UTF-8 JSON、按完整路径或设备实例精确选盘的脚本；应把程序放在本地磁盘运行。

[USB Safely Remove](https://safelyremove.com/features.htm) 提供设备重命名、阻塞程序处理、设备专用快捷键、恢复已停止设备和连接事件自动运行。USB-Switch 已覆盖其中常见的人工操作。具体文件定位、隐藏指定设备、每设备快捷键，以及插拔前后执行备份等任务，仍有差距。若继续迭代，建议优先增加隐藏指定设备及按需查看占用文件：前者减少多盘菜单干扰，后者直接改善“知道哪个程序、却不知道关闭哪个文件”的情形。
